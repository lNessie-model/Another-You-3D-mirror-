# Live scene controls and screen-plane backgrounds

The main screen's **画面** button opens a floating live draft. It controls uniform scale, three translations, three rotations, total camera span, convergence plane Z, and background. Cancel, Back and Activity pause restore the original snapshot. Save explicitly commits the separate `mirror-scene-view` schema-1 preferences; it does not change `mirror-runtime` schema 4 or avatar selection. Unknown scene schemas are protected from overwriting. These settings are not yet included in the unfinished full configuration backup UI.

Translation X/Y is measured in display half-width/half-height at the original Z=0 plane. Z and the convergence plane use the renderer's normalized world, with cameras at Z=3. Positive Z moves toward the viewer. The camera control is the total left-to-right span; adjacent view spacing is span divided by (views−1). Each camera remains parallel and uses an off-axis frustum, so points on the selected convergence plane have zero disparity. Scaling/translation can crop the model. This software geometry does not establish physical optical alignment.

Pitch, tan and offset/phase remain under **维护 → 屏幕校准**. Pitch units are explicit; offset is in cycles, with 1 meaning one complete grating cycle. Saving normalizes it to [0,1). The current device uses pitch 10 subpixels, tan 0.2777777, offset 0, RGB, bottom origin.

The first eight backgrounds are procedural; the next four are bundled PNGs. Backgrounds occupy the screen plane and are composited during the existing final interlace pass. Runtime avatar views clear to transparent black, and RGB channel samples use their own alpha coverage. No background mesh or extra per-view background pass is added. A GL-context-owned texture holds only the selected image, replaces its previous storage on image changes, and deletes it when a procedural background is selected. Decoded bitmaps are recycled after upload. A new EGL context receives a new owner; predecessor texture names are never deleted in the successor context. Broader runtime GL teardown remains separate pending work.

The four 992×1586 opaque image previews were generated with the built-in image generator on 2026-10-04. Canonical previews, metadata and prompts are in `E:/tripo/assets/mirror-backgrounds-20261004`. APK image bytes match the originals. Each image occupies 6,293,248 RGBA bytes (about 6 MiB) while selected, without mipmaps. Image decode/upload occurs once on a selection change, on the GL thread; it can briefly delay that frame. There is no per-frame decoding or all-image RAM cache.

## Mirror response additions, v26

Scene schema 1 accepts two additive optional fields: `mirror_motion` (Boolean, default true) and `expression_gain` (Float, default 2.5, range 0.5–4). Old maps retain all previous values and gain these defaults in memory; loading does not write them. All immutable edit/background methods preserve both fields, and explicit save writes booleans with putBoolean. The floating panel has a mirror checkbox and mouth/brow strength slider; cancel/Back still restore the original full snapshot.

Render-side mapping swaps canonical anatomical Left/Right channels and reverses yaw/roll while preserving pitch, without negative model scale or reversed optical view order. Mirror is currently applied after the interaction mapper; the current device's earlier personal-calibration mirror is false. A future integration should consolidate the two mirror ownership points before claiming all possible saved personal-calibration combinations are supported.

v25 multiplied non-gaze channels and clipped them to one. User confirmed mirror direction but reported eye overclosure. v26 preserves all eye coefficients, cheek squint and mouthClose, and uses an endpoint-preserving response on the remaining channels. A strength of 2.5 is a curve parameter, not direct multiplication. Existing rig product corrections consume these mapped coefficients once. The applied snapshot status labels raw/mapped blink and jaw values and response policy. Tests: 335 mapping/legacy preference/physical reflection checks, 778 unchanged view checks, 107,907 camera-cache checks. The full offline APK build passes. v26 face-present visual validation remains pending; no v26 30 FPS claim is made.
