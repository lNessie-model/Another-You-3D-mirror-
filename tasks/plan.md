# Another You 正式 App 实施计划

保留完整目标：正式UI/操作逻辑、全部既有资产、逐模型校正、每通过一版Git同步；16+视点30FPS仍须实际完成与证明。

依赖：规格 -> V31产品入口/主题 -> 设备导航验收 -> 提交/同步；资产清单 -> bundled catalog协议 -> 逐模型离线校正/真实预览 -> V32接入 -> 设备加载/联合性能 -> 版本同步。可并行：UI组件、只读资产审计/校正、catalog纯逻辑；root唯一ADB操作者，repo_sync唯一Git写操作者。

V31分片：
1. 正式单入口与主题（新HomeActivity、主题工具、manifest） -> 构建/launcher/权限。
2. 实时中央安全区菜单与状态（MirrorActivity最小UI接入、新RuntimeControls） -> 构建/状态/返回/权限。
3. 复用原设置事务，首页入口接入、真实产品版本 -> 保存取消回归/实际APK检查。
4. 设备导航/截图/升级/退出资源验收 -> 冻结V31 -> 普通推送与远端SHA。

V32分片：
5. 跨十角色实际资产清单、预算及原始/最新源对照 -> 逐项结构/rig检查。
6. BundledAvatarCatalog/选择状态稳定协议与测试 -> 不删除导入三槽。
7. 逐角色自拓扑校正及PBR预算，闭眼/眼宽/眉/嘴/牙组合门槛 -> 真GLB姿态预览。
8. 包内角色与背景接入/懒加载 -> 逐模型GPU加载/切换/用户配置持久化。
9. 全库覆盖、16视点联合性能测量与优化 -> 验证通过版同步。

失败风险：重复asset膨胀/多角色全量解码/旧GL资源泄漏/镜像与校准混淆/装机签名不匹配/旧状态被当成新状态。对应以清单去重、metadata列表、显式owner生命周期、原流程复用、签名及回滚、boot新会话验证约束。
