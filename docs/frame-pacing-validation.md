`fence wait` 是 CPU 在 `glClientWaitSync` 内的墙钟耗时，已包含在 `callback work`，不能相加后当成独立 GPU 耗时。`callback gap` 从上次 work 结束到下次回调进入，包含状态发布、EGL/framework 和调度时间，不能称为单独的 swap 或 GPU 时间。不同计时项的边界与分母不同，不应简单相加后倒数来替代 SurfaceFlinger FPS。

35 组减少约 1.20 ms 的平均节拍等待，但同期 work/gap 更高且实际呈现 FPS 未获收益。连续 31/35/31 为额外对照，仍不是随机顺序、等温、独立变量完全隔离的因果实验；当前结果足以否定“仅提高目标就已达 30 FPS”，不足以从 GPU 忙碌均值断言唯一 CPU/GPU 瓶颈。下一步应分段量测实际提交与计算成本。
