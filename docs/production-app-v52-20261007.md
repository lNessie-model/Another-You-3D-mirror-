# V52 / 0.2.21：个人眉部基准与更多头部预设

本轮改善静止时持续皱眉的映射，增加宿傩试用角色，并把新生成的头部原件和真实 GLB 预览打包到素材库。默认仍是杰洛特，正式黑金暗红椭圆界面与原渲染材质保持。

## 更自然的眉部映射

个人中性基准增加左右 browDown 静止值。确认基准后，使用 `clamp((raw-rest)/(1-rest),0,1)`，随后才执行镜像；静止偏置归零，真实最大皱眉仍映射到 1。旧七参数基准和未校准行为保持原结果。没有统一放大眨眼、微笑或张口，也没有宣称本轮重新制作了杰洛特眼睑、嘴部或牙齿。

入口：设置 → 相机与动作校准 → 保持勾选“本次同时校准个人眉眼、嘴部与视线偏置” → 正视、眉毛放松、自然睁眼闭口约两秒 → 采集中性 → 确认本次中性。需满足稳定、独立、连续约两秒的有效帧；眉部静止值超过 0.5 拒绝采集，以限制归一化增益不超过 2。这是工程界限，不能证明用户真实放松。

基准需要用户明确采集和确认，只保留在本次运行。取消退出、离开镜头、切换输入或重启需重新采集。录像测试不能通过相机校准入口建立用户个人基准。相机失败时，采集、确认和保存安装设置禁用；仅取消回设置的实机流程得到验证，成功实时个人采集未验收。

三类生产代码、三类测试与校准页经过独立代码检查。四个相关测试入口共 10,601 项检查通过；先保留偏置未消除的失败，再修复验证。另以实际 Java Collector/Mapper/Playback/Rig/Deformer 合成输入输出杰洛特原 PBR 的中性、皱眉与挑眉预览。这些是合成输入的离线 Blender 检查，不能当本人实时面捕或实际 Mali 画质验收。

## 实际联合回放

同一 V52 APK、宿傩、原完整 PBR、普通 individual/bounded-worker 路径、16 个独立 400×640 视点、1200×1920 交织、既有 NV21 录像、RGA/RKNN478 和混合 CPU/NPU52 后处理同时运行，采集 45 秒。不是 USB 实时采集或视频解码，也没有开启材质/切线实验。

主要确认 INTERACTIVE 区间 34.614 秒有 331 次呈现，SurfaceFlinger 实际约 **9.559 FPS**。末尾另有 6.758 毫秒 INTERACTIVE 片段无呈现，完整活跃证据门为 false，原始结果保留；不能将主要区间当全程完整门，也未达到 30 FPS。没有同包杰洛特性能对照，不能据此断言 V52 性能回归或提升。

确认交互区间资源：全机 CPU 51.17%，GPU busy 98.18%，NPU busy 39.97%；App PSS 七次样本平均 266.85 MiB、最高 385.34 MiB；温度 62.22–65.63°C。PSS 含录像 mmap 驻留，非独占分配。

最新输入会话 573 完成帧、572 人脸帧，覆盖 99.83%，478 点/52 表情；会话面捕约 16.20 FPS，接收到完成平均 98.04 ms。会话推理均值含获取/闲置，不能与交互区间资源混为同一范围或把各阶段 CPU wall 相加成 NPU 独占耗时。各嵌套状态不是联合原子快照。
