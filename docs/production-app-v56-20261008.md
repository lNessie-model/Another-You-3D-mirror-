# V56 / 0.2.25：杰洛特嘴型与口腔改良

用户反馈大张嘴时嘴型不自然、口腔像黑洞。本版修正张嘴驱动、下唇形变、牙弓和口腔材质，已在原 Android 11 设备同签名覆盖安装。正式模型仍为杰洛特，素材库和另外三个实时角色保留。

## 行为变化

`jawOpen` 原来使用统一表情增强，增益 2.5 时输入 0.3 变为约 0.59，容易将轻微开口放大。现在 `jawOpen` 与原有 `mouthClose` 各自保留传入系数，微笑、眉毛等通道继续使用既有增强；镜像、眼睛映射和保存的设置不改。

这里的输入已经经过面捕过滤和个人基准处理，并非必然等于原始 MediaPipe 数值。其他唇部通道、模型下颌转角仍影响最终开口，不能据此声称人与模型的嘴型完全一致。

根据用户对口腔细节仍简陋的反馈，最终版把杰洛特的下颌贡献收小 20%：`jawOpen` 绑定增益从 1 改为 0.8，`correctiveJawOpenMouthClose` 乘积补偿增益同步为 0.8，下颌附件转角从 15° 改为 12°。三者同步，以免只缩唇部形变却让牙齿仍按大角度转动。这个角色级限制不修改保存的全局增益，也不改变另外三个角色的 manifest；微笑、眉眼和其他唇部通道保持。

32 组真实 Java 输入组合验证，这三项修改与旧版先将下颌输入乘以 0.8 的全部网格权重、活动节点矩阵误差为 0，其他目标权重字节一致。只证明下颌贡献缩小 20%，不等于嘴缝面积精确减小 20%。大幅张嘴仍可发生，但不再把当前简化口腔暴露到原来的范围。

杰洛特下唇使用宽而连续的正向形变场，中心最大修正约 1.35mm，避免先前局部修正造成的 W 形。同步补偿 `jawOpen × mouthClose`，保持闭口。口角局部法线用 8 个自身三角形角点分离修正，各点位置、UV、顶点色及所有形变复制自身来源；没有重建眼睛或更换头部贴图。

上下牙弓中间八颗牙冠缩短、收窄并后移，边缘两颗保留原完整牙冠以避免闭嘴露牙；舌头略上移前移。牙冠颜色未提亮为纯白，牙齿仍为轻量模型，有简化感。

原口腔材料额外乘以 0.2，实际纹理解码后舌头与牙龈仍很暗。现在保留 lit PBR，将该系数改为 1，重新设置内壁、牙龈、舌头的柔和红色梯度，口沿颜色反向补偿以保持原有效颜色；粗糙度 0.94 改为 0.62。口腔深处仍有阴影。没有使用 unlit、自发光或全局灯光变亮来掩盖问题。

## 已完成验证

映射测试先以旧实现失败，再以新实现通过：FacePlaybackTest 1,547 项、FaceExpressionResponseTest 463 项，共 2,010 项。新增检查覆盖六个增益、两种镜像及 101 个张嘴系数。独立源码评审未发现新增 P1/P2 阻断项；它未重跑上述作者测试。

11 个实际 Java 形变姿态检查未增加翻面、法线反例、退化或非有限坐标。四种闭口组合、三个视角的 720 个离散牙冠探针均无露牙；这是有限采样，不是连续全表情碰撞证明。闭口组合补偿误差约 3.73e-9 米。眼部与注视点位置、法线保持原件。

最终设备完成九姿态 × 16 层数组视图比较和十张 PNG，317 项宿主检查通过。串行与 OVR4 比较的 RGBA 严格零差，单层和批量路径按原 maxRGB≤1 / RMSE≤0.1 / alpha=0 门限通过。这验证新模型的不同绘制路径一致，**不表示 V55 与 V56 画面相同**，也不是最终交织或裸眼光学验收。

APK 有 99 项资产，只有杰洛特 GLB、manifest、实时角色 catalog 与素材库 catalog 四项按批准输入修改；其余 95 项资产和九项原生库与 V55 字节一致。签名保持，同签名覆盖安装与首页启动通过，四份配置字节一致。实机预览结束后 14 项诊断文件和四份配置精确恢复，返回首页。

## 作者工具与继续改进

新增 [口腔颜色作者工具](../scripts/author_geralt_oral_colour.py)，仅接受批准的 Geralt 原布局或本版 8 点分离布局及各自 UV/索引/语义 pin；错误布局和已有输出目录会被拒绝。它只编辑明确归属的口腔和牙龈颜色、口腔材料，逐项保护几何、法线、UV、牙冠颜色、贴图、形变与节点。工具输出报告默认不代表实机或美术验收。

工具用于还未做本版口腔颜色编辑的几何候选；已经发布的 V56 因材料已修改，不应直接再次运行。几何作者链还依赖多份私有中间候选，暂不作为独立可重用 CLI 发布；最终 GLB、绑定 manifest 和本版验证说明已进入工程。没有把未完成的源工程改动混入发布。

示例：`python scripts/author_geralt_oral_colour.py --model <几何候选.glb> --manifest <该候选avatar.json> --out <全新目录>`。修改后仍需重验闭嘴、组合表情与设备真实画面。

本轮未消耗 Tripo 积分。牙冠、舌头和口腔内壁仍为简化结构；目前改善了黑洞感与过度张嘴，尚未达到解剖级或写实口腔效果。没有全历史角色的嘴型验收，没有本轮本人 USB 摄像头面捕验收；16+视点 30FPS 目标仍未完成。

## 首版 v1 正常入口录像联合冒烟（不是最终缩幅版性能）

缩幅前的 v1 APK `7140ff29579677af0d3b7feac5443cc169aabce06d4a2410d8f14f678b305c9d` 只运行了一组 25 秒采集，正常捆绑角色入口、既有录像 NPU 面捕、16 个独立 400×640 视点共同运行，没有重跑 ABA 或长时测试。实测 run_id 为 `c777d433-ffdc-439e-b307-1fc4dd3d616e`。启动结束后的可确认 INTERACTIVE 窗口约 9.6949 秒、101 个实际呈现帧、10.394346 FPS；这里不能把整个 25 秒都称为稳定互动窗口，30FPS 没有达标。不能将这个数值当成最终 v2 缩幅版本的已测性能。

采集器真实退出 0，随后外围包装器在检查模型身份时将启动期 `avatar:null` 当字典，真实退出 1；原失败日志保留。后续只用已有原始数据做空值安全复核，没有为取得绿色结果重新采集。三条实际加载记录确认杰洛特正式 GLB 和 16×400×640，跳过一条启动空记录。性能不能仅按这个有限窗口与前版比较。四配置、原 runtime status、录像 SHA 和安装包身份精确恢复，返回首页。最终 v2 未重跑录像 FPS，本轮不能宣称帧率改善。
