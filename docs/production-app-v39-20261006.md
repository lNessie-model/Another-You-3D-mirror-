# V39 / 0.2.8：比例视图分辨率实验

V39 增加 `240x384`、`200x320` 两个**调试会话专用**分辨率，用于测量降低每视图采样成本的收益。普通首页、设置、角色和场景沿用 V38；日常默认仍是 16 视点 / 400×640。两项候选不在保存配置的允许表中，不会因为测试而写入原配置，也没有成为产品画质档位。

APK SHA256：`2d5e4fab5c10e1e116b28ea0f4631e018855f52aad1c45a71b1aa80ed948f64f`，versionCode 39 / versionName 0.2.8。覆盖安装保留原内部签名与 ADB。78 个 assets、9 个 native entries 与 V38 逐字节相同；模型、绑定、背景、PBR 源码和推理算法未改。

## 实测条件

同一 APK、同一动态 NV21 人脸录像、RGA 转换、RKNN 检测/478 关键点、CPU 规范化与混合 CPU/NPU 52 项表情、完整杰洛特 19,907 顶点 / 19,157 三角形、原 PBR 材质与贴图；16 个实际视图、OVR4、合并绘制、固定 FBO、相机矩阵缓存和异步形变。输出 1200×1920，光学及场景配置字节保持。测试中的视图尺寸均为 10:16；投影始终按物理屏幕比例 0.625，不随采样尺寸变化。

原 / 240×384 / 200×320 / 原，各收集 45 秒。所有 GPU query pool 为零、ORM RG8 和 PBR 算术候选关闭。采集中没有截图或像素读回；下面的图像筛查在性能收集结束后单独执行。FPS 使用 SurfaceFlinger 实际呈现时间戳，仅计已确认的 INTERACTIVE 时间；不用 callback FPS 替代。录像测试**不含 USB 采集与视频解码**。

## 完整收集结果与限制

| 每视图尺寸 | 组别 | INTERACTIVE 呈现 FPS | 完整呈现证据 |
| --- | --- | ---: | --- |
| 400×640 | 原始首次 | 8.927 | 通过 |
| 240×384 | 候选 | 12.385 | **未通过** |
| 200×320 | 候选 | 13.361 | 通过 |
| 400×640 | 原始复测 | 8.909 | 通过 |

240×384 收集末尾有一次未检出人脸，进入约 278ms 的 GRACE 后恢复；新的 INTERACTIVE 区间只有 6.085ms、0 个呈现帧，因此严格的 `complete_active_evidence=false` 原样保留。该组 12.385 是有完整历史的较长区间的估计，不能称全程通过或持续 30FPS。所有原始收集、失败门、日志和状态事件保留在本地 QA，不覆盖后重算为通过。

为可比地观察资源成本，在首两组收集后、200×320 和复测收集前，明确增加每组首次 INTERACTIVE 起固定前 25 秒的辅助窗口分析。它是后加的统一分析，不能冒充最初预注册方法，也不取代完整收集验收。四个辅助窗口均有完整实际呈现历史，窗口内状态快照的人脸成功比例为 1。

| 每视图尺寸 / 组别 | 辅助窗口 FPS | CPU 全机均值 | GPU 均值 | NPU 均值 | App PSS 均值 MiB |
| --- | ---: | ---: | ---: | ---: | ---: |
| 400×640 首次 | 8.937 | 57.17% | 98.63% | 49.71% | 241.41 |
| 240×384 | 12.407 | 68.35% | 98.54% | 48.67% | 210.71 |
| 200×320 | 13.394 | 70.51% | 99.00% | 50.46% | 210.99 |
| 400×640 复测 | 8.915 | 56.60% | 98.56% | 48.48% | 244.54 |

这些是顺序短测，温度、缓存和首次加载有漂移；不能作长时间稳定性、严格因果或实时摄像头内存结论。辅助窗口末次面捕快照的会话均值约 14.88 / 12.26 / 11.89 / 15.03 FPS，范围包含各自推理会话，并非逐帧对齐到 25 秒窗口；低档渲染加快时 CPU 工作增加，面捕速度也下降。并行阶段的在线均值不能相加成为 GPU 时长。

**结果：缩小采样尺寸有明显帧率敏感性，GPU 仍约 99%，最好约 13.4 FPS，未达到 16+ 视点 30FPS。** 200×320 的完整短测比两次原档均值约快 50%，但画质尚未验收，默认产品性能未改变。

## 画面与功能验收

- 另行捕获三个分辨率的实际交织输出：同模型/材质与参数，但回放姿态不同，只用于画面筛查。普通显示器上的截图会显示交织条纹，不能代替现场裸眼 3D 光学验收。
- 初次 400×640 截图未核对新会话，误读旧状态且截图空白，已拒绝并保留。第二轮强制新 session、GL 首帧、等待呈现及再次读取状态，三个实际截图可见角色和背景。不能把失败截图列为画质通过证据。
- 尚未完成相同姿态下的 16 层独立 hash/alpha 覆盖与中心视图对照；没有声明低分辨率等价、艺术质量通过或可默认启用。
- 真机关于页显示 0.2.8（39）。原设置页跳转/返回、普通入口恢复 16×400×640、完整杰洛特、reference PBR、候选关闭与 query pool 0 均检查通过；测试后四份原配置 SHA256 精确保持，回到首页后无 GLThread / AvatarPose。
- 普通相机入口仍有 `CAMERA_ERROR(3)` / `endConfigure` 流配置错误。自动错误菜单存在时第一次 Back 收起菜单、第二次返回首页，这是实际观测，不声称本版已经解决所有返回层级问题。

## 构建与检查

SDK35 / JDK17 离线构建成功（16s）。调试 preset 在真实 InputOptions 与实际 createRuntimeRenderer 路由到新宽高；release、null、错误类型和未允许尺寸拒绝，保存机制保留原允许表。新增检查先在未改生产白名单时失败，再经白名单扩展通过。

当前相关主机检查：RuntimeViewCount 12,960 项、实际产品路由/保存 107 项、ViewPresetSettings 114 项、MirrorSettings 17 项、CameraControlSettings 56 项、PBR 默认/配置 22 项、GL 生命周期 34 项、输入停止 1,481 项通过。它们各自的 host/fixture 范围不等于真机 Camera2、NPU、GL 像素资格，也不等于重跑全部历史测试。

旧 ProductRuntimeViewCount 的 Unsafe 夹具绕过正常字段初始化，缺少 sceneViewSettings。用 V38 原 MirrorActivity 独立编译运行同测试也在第 47 行抛出 `Scene view required`；本版给两处夹具补入真实 SceneViewSettings.DEFAULT，不删生产空值校验。
