# 相机输入方向的像素合同

`CameraInputTransform` 是未接入实际摄像头的纯 Java 基础模块。它在整数像素、左上原点坐标中执行 **顺时针旋转 0/90/180/270°，随后在旋转后的画面中做可选水平反射**。90/270° 交换宽高。它不改变角色动作、表情左右或屏幕交织参数。

调用者持有并复用输入/输出 ARGB 数组；`applyArgb` 不分配逐帧缓存，整整数复制保留全部 Alpha 和颜色位。恒等变换允许同数组，其余变换在写入前拒绝别名。容量不足、非法坐标、非法角度及超过 16,777,216 像素的尺寸在操作前拒绝；变换后数组的额外容量不写入。这是 CPU 参考实现，没有声称使用 RGA 或零耗时。

顺序尤其需要在 UI 和录像元数据中写清楚：`H·R`（旋转后水平反射）与 `R·H`（原始画面反射后旋转）在 90/270° 时不同。不能直接把相机声明的原始 mirrored 标志当作本开关。实际安装应使用非对称、文字可读的方向卡确认规范输入，不能仅凭对称人脸确认。

验证命令：

```powershell
.\tests\run_camera_input_transform_tests.ps1 -JavaHome 'C:\Program Files\Java\jdk-17'
```

872 项主机检查使用手写的 3×2 非对称像素期望值覆盖八种组合、矩形及单行/单列边界、正反坐标映射、全 ARGB 位、容量和别名。测试先因缺失实现失败，实现后通过，并经过独立只读复核。这不验证 Android Bitmap、YUV/RGA、相机 metadata 或推理方向。
