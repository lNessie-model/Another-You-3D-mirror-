# Opt-in geometry + normalized RKNN expression composition

This adds two independent Java classes without changing the existing `FacePostGraph`, production pipeline, activity, assets, native libraries or default configuration. The host checks pass; the new path still needs Android graph/JNI and full joint-load validation before use. The underlying fixed suffix's isolated numerical evidence is recorded in [normalized suffix device validation](blendshape-normalized-suffix-device-validation.md).

## Interfaces

`FaceGeometryPostGraph(String metadataPath, boolean smoothing)` retains the original MediaPipe graph's five geometry-related nodes and their stream wiring. `process(float[] xyz, int width, int height, long timestampMs)` synchronously returns `Result`, with owned copies of 1,434 smoothed XYZ floats and 16 column-major canonical-pose values. `landmarks()` and `pose()` return copies. There is no 52-element placeholder or neutral fallback. `close()` is idempotent.

`NpuExpressionPostGraph(String modelPath, String applicationApkPath, String metadataPath, boolean smoothing)` composes this graph with `NormalizedBlendshapeInput` and `RknnExpression`. It may throw `IOException` during model/runtime verification. Its synchronous `process(...)` returns exactly `float[][] {weights52, pose16, landmarks1434}`, published only by `BlendshapeSchema.copyValidatedPostOutput`. Weights retain their original schema order and strict existing `[0,1]` validation; no clipping is added. `reset()` closes/recreates both dependencies and clears OneEuro/history/latched failure only after full initialization succeeds. It may throw `IOException`. `close()` is idempotent; `summary()` returns a fresh `JSONObject` and may throw `JSONException`.

The methods are package-private like the old postprocessor. `process`, `reset`, `close` and `summary` share one monitor. There is no internal queue, additional worker, pipeline fallback or parallel invocation within this wrapper. The existing caller owns backpressure and must keep input immutable until the call returns. Sequential ownership may transfer between caller threads; there is no construction-thread restriction.

## Preserved geometry and normalization

The graph retains `TensorConverterCalculator`, `TensorsToLandmarksCalculator`, `LandmarksSmoothingCalculator`, `ConcatenateNormalizedLandmarkListVectorCalculator`, and `FaceGeometryFromLandmarksGraph`, with the same metadata file and two graph threads. Only the CPU expression node/options/stream are removed. Both `coords` and `size` packets receive the same `timestampMs * 1000` as before. Timestamp values must be nonnegative, safe for microsecond conversion and strictly increasing within a generation; reset is needed for a new time origin. Both supported oriented input sizes are 640×480 and 480×640, matching the separately tested normalization class.

The landmark and smoothing options encoders were copied unchanged from the existing class. Host tests invoke the **actual existing private option builders** and compare serialized protobuf bytes, for both OneEuro and disabled smoothing; they do not extract snippets or compile a mirrored implementation. OneEuro remains min_cutoff `.05`, beta `80`, derivative cutoff `1`. Pose still uses the same `FacePoseMatrix.copyValidated` (one 4×4 COLUMN_MAJOR matrix, bounded metadata/finite checks). All 478 XYZ values must be finite.

The expression input is built from the graph's **smoothed** landmarks, not the incoming unsmoothed array: official146 selection → pixel XY → original FP32 mean-Euclidean-radius normalization → exactly 292 adjacent float32 values. One owned direct native-order 1,168-byte buffer is reused, with absolute writes, position zero and full limit. `RknnExpression.run` handles the fixed model/runtime/actual tensor contracts and returns 52 values. Its independent SHA, JNI and device requirements are in [JNI validation](rknn-expression-jni.md).

## Failure and ownership behavior

Geometry's two input packets use nested try-with-resources, covering second-packet construction, enqueue, idle-wait and packet-release failures. The callback validates one pose and exactly 478 points before creating an owned result. No result is reused after a failure. Constructor failures attempt teardown and retain the primary error. Closing a graph tries to close sources and wait for completion, then always attempts teardown; if source closure fails, it skips the potentially indefinite end-of-stream wait. The graph and creator references are detached before cleanup, preventing repeated destruction.

The composition opens geometry, then expression, then reads metadata. A failure at any point closes all resources already acquired; later cleanup failures are suppressed onto the original exception. Live adapter objects are allocated before their native resources, eliminating an allocation gap between native open and owner creation. Process failures latch the session, record failure, and attempt both resource closes. Later calls fail before external work until explicit reset/recreation. Reset cleanup failure leaves the wrapper faulted and opens no replacement. Close always detaches both resources first and attempts both even if the first close fails. A second close does nothing.

Each live generation owns one graph, one native expression context, and one direct input buffer. Java result/normalization copies are fixed-size; there is no growing frame cache. This is a bounded-resource contract, **not a hard timeout guarantee**: underlying MediaPipe/RKNN blocking calls are synchronous and cannot be forcibly cancelled safely by this wrapper. The application's existing lifecycle/watchdog still owns recovery policy. Reset rebuilds both resources and can incur model/runtime hash/read/init costs; those costs need device measurement and are not hidden in per-frame averages.

## Timing and metadata

`summary()` exposes attempted/successful/failed frame counts, generation/reset counts, per-stage attempt counts, total and mean milliseconds for geometry, normalization+packing, and expression API, validation total, and total process wall time. Attempt counters include failed stages; a stage that was not entered is not counted. Empty averages are JSON null. Statistics remain cumulative across explicit reset; init/reset costs are excluded. A total for a failed process includes cleanup. The outer monitor wait before method entry is outside these measured intervals.

These are **CPU-observed wall-clock intervals**, not CPU execution time, GPU time, NPU utilization or FPS. Expression API wall time includes SDK waits, CPU fallback and IO conversion. The snapshot includes the fixed model SHA and last successfully read complete native model-info JSON; that metadata is retained and clearly labeled after close/failure. A snapshot's `closed`/`fault` must be read with it. This class does not claim the old CPU network's entire post time has disappeared or that the application's render target is met.

## Actual host validation

The first new test failed to compile because the production composition class did not exist (RED). The final new runner compiles all production classes involved against actual SDK35, MediaPipe Tasks and protobuf jars, plus the existing pinned JSON library. It does not substitute an Android/MediaPipe graph implementation. Host execution supplies only narrow fake external `Geometry`/`Expression` dependencies, an explicit normalizer fault hook and a deterministic clock; the production composition and transaction logic are the code under test. One test uses the **actual default CPU normalizer** and asserts all 292 submitted floats come from smoothed geometry rather than deliberately different raw input.

- `FaceGeometryPostGraphTest`: **32 checks**, real protobuf graph node/stream/metadata/options preservation for both smoothing settings.
- `NpuExpressionPostGraphTest`: **386 checks**, stage order, complete 52/16/1434 output and ownership, real normalization submission, no channel reorder/pose transpose, input and timestamp validation, every-stage failure/latched faults, no downstream submission after failure, partial initialization, metadata failure, both cleanup errors, close idempotence, failed reset and explicit recovery, no clipping, and close blocked behind an active transaction.

Command: `tests/run_npu_expression_post_tests.ps1`. The first SDK read was denied by the host sandbox before compilation; the authorized host-only SDK read then compiled and ran the suite successfully. No Gradle/APK build, native inference, Android graph callback or ADB action was performed by this slice. Therefore packet callback/layout identity, APK loading and device timing still require the root operator's separate checks. No existing source, manifest or build file was edited.
