# 本地角色管理入口

`AvatarManagementActivity` 使用 `files/avatars` 的 `AvatarPackageStore`，仅 Android 11/API 30 及以上支持导入。系统 `ACTION_OPEN_DOCUMENT` 选择 ZIP；只持临时读 URI 权限，不请求全部存储权限、不上传内容、不持久记录文件 URI。

流程是后台导入/严格文件验证、单视点真实 GLES 预览、用户点击使用、Store 对 exact Ticket 重新校验后原子切换。候选从未自动成为当前；上一版也必须加载并预览后 `restorePrevious(ticket)`；内置角色从 APK 在后台读入并核对 SHA，预览后才 `activateBuiltin()`。界面提供中性、闭眼、张口和头转。预览按物理 0.625 比例居中，不把 GLSurfaceView 分配的宽高误作角色比例。文字明确只支持当前 loader 的表情/刚性关节/顶点颜色配置，不声称支持纹理或蒙皮。

后台执行器进程内最多一个运行任务和一个待处理任务。所有 Store、文件读取与包验证都在后台；GL 对象必须在 GL 线程创建，其 `fromAsset` 工厂仍有建 rig/变形器/包围盒的 CPU 初始化工作，不能在 UI 线程执行。同步预览没有 NPU 或相机任务。

每次恢复/选中都有独立 owner token；候选身份和 GL context 身份必须都匹配，且一次 `draw`、`glFlush` 后没有 GL 错误，才允许“使用此角色”。该证据只代表成功提交和 API 错误检查，不能证明 SurfaceFlinger 已呈现、动作美术质量或光学效果。HOME、返回、重新选择立即使旧回调和启用资格失效。上下文丢失必须重新成功绘制；旧 EGL 名称不能在新上下文删除。实际 `eglGetCurrentContext` 也参与清理检查。

暂停取消 Future 并关闭当前文档流，关闭动作有独立有界后台线程，UI 不等待后台任务 join 或文件 IO。如果提供方在 `openInputStream` 中永久阻塞，无法取得流来关闭；提供方也可能忽略中断/关闭。单工作线程仍保持有界，不能保证强行终止提供方；后续请求不会新建替代 IO 线程或绕过 Store 锁。

页面以 `elapsedRealtimeNanos` 的单调时间设有限截止时间：文件读取/验证包含排队最多 30 秒；CPU 文件加载完成后才开始 GL 首次预览的 20 秒；用户明确点击切换后最多等待 15 秒确认。创建空 GL context 不占用或改变文件阶段的截止时间；等待 GL 期间反复重建 context 不续期。已成功预览的静止页面没有截止时间；随后丢失 context 必须在新的 20 秒内重新提交成功绘制。HOME/暂停撤销 owner 和截止时间，恢复后从新的读取请求开始。

主线程每 250 ms 检查，加载/GL/切换成功回调也检查截止时间，迟到回调不能赶在下一次轮询前冒充成功。超时一次性撤销 owner 和 GL 资格，取消 Future、移除待执行任务、异步关闭已取得的文档流，清空本次预览并恢复“重新读取”/“返回”等按钮；维护详情记录阶段、经过时间和预算。因此即使唯一工作线程被提供方占住、后续读取已进入队列，也不会无限显示 busy。重新读取仍可能超时，需等待该提供方恢复。该截止时间依赖 Android 主线程继续调度，不声称能硬中止卡死的 GL 驱动或消除 `GLSurfaceView` 自身的生命周期等待。

取消并非硬终止：Store 会在原子 rename 前检查中断，但已经开始的原子提交不能撤销。切换超时或异常只显示“结果尚不确定/未能确认”，不会宣称未提交的操作成功，也不会保证磁盘选择仍是旧版本。返回管理页面后会重新读当前；调用方 MirrorActivity 在管理页面任何结果返回时重建并重读选择，以涵盖提交成功但 UI 成功回调被暂停丢弃的情况。

摘要损坏只显示明确维护警告，不阻断独立验证健康包或预览内置角色；不会静默覆盖/删除坏目录状态。如果 selection state 本身损坏，内置仍可预览，但切换可能被 Store 拒绝，需要维护处理。维护详情最多 2048 字符，显示名最多 80 字符；没有持续逐帧日志或图像保存。

门控测试 24 个断言覆盖无预览禁止启用、错误候选、重复点击、HOME 取消、旧 IO/GL 回调、上下文重建、陈旧清理、GL 失败撤销及失败后重试。截止时间测试 42 个断言使用显式可控时钟检查精确边界、加载到 GL 的归属转换、context 重建不续期、成功后静止页面不超时、暂停/恢复、迟到成功不能抢先通过、切换结果不确定；另用真实单线程有界 executor 和忽略中断的 latch 模拟阻塞提供方，证明无需 IO 回调即可撤销队列中的请求并移除它，没有新建替代工作线程。用 latch 释放仅为测试清理，不表示真实提供方一定可解除阻塞。新增截止时间测试先因缺少契约编译失败（RED），实现后通过（GREEN）；另在隔离的构建副本中禁用超时分支，测试在首次 30 秒边界按预期抛出断言，确认测试能捕获缺失截止时间的行为。

真实 Store/ZIP/parser 的 6 项回归用坏 candidate 摘要证明原始 `readCatalog` 会失败，而 Activity 适配器保留警告且健康 current 仍可读取，不改写坏数据。SDK 35 jar 用于完整 Manager 源码编译链接和静态适配器类加载；不把 SDK 的 stub 当真实设备执行。

v9 设备已验证：实际 SAF 有效 ZIP 导入并预览、候选不自动启用、B/A 显式切换、无效 ZIP 拒绝且保留当前、上一版回退、进程重启后读取及恢复内置；完整原始状态、哈希和边界见[设备验收记录](avatar-management-validation.md)。v8 的 StatFs 修复前错误不是无效 ZIP 校验通过。现场没有人脸，这些管理测试不证明完整面捕负载或性能。
